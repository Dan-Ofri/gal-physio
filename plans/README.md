## Recommended execution order

1. **002** first — defines `--ease-out`, `--ease-in-out`, `--ease-drawer`, which 004 and 006 reference (each also documents a literal-value fallback if run out of order).
2. **001** and **003** — independent of each other and of 002; can run in any order, or together, or in parallel by different agents (touch overlapping files — `Nav.astro` — so if run in parallel, apply sequentially to avoid merge conflicts on the same `<style>` block).
3. **004**, **005**, **006** — independent of each other; 004 and 006 depend on 002 (see above). 003 and 006 both touch `Nav.astro`'s reduced-motion handling — if both are selected, apply 003 before 006 and merge 006's reduced-motion rule into 003's existing media-query block rather than adding a second one (006 notes this explicitly).

## Dependencies at a glance

- 004 → 002 (easing token; has a documented fallback)
- 006 → 002 (easing token; has a documented fallback)
- 006 → 003 (soft dependency: merge reduced-motion blocks if both touch `Nav.astro`; not a hard blocker)

## Not planned

Two additional observations came up during the audit but weren't written into plans (surface them again if they become relevant):

- **Positioning is unconfirmed** (see `PRODUCT.md`) — none of these plans depend on messaging/positioning, they're pure motion-quality fixes, so this doesn't block them.
- Tailwind v4's `hover:` variant already compiles to `@media (hover: hover)` by default, so "ungated hover on touch devices" was checked and is **not** a finding in this codebase — omitted rather than reported as a false positive.
